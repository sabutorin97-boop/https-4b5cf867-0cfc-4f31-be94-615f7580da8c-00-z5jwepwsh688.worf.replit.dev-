# Окна Профигрупп — лендинг с квизом

Одностраничный сайт для оконной компании. Главный блок — квиз: посетитель
отвечает на шесть вопросов, получает подобранную комплектацию окна и оставляет
заявку на замер.

Цену квиз намеренно не считает — она известна только после замера, и обещать
цифру заранее значит обманывать клиента.

Стиль взят с сайта `ai-profigrup-studia`: тёмная тема, сине-фиолетовый градиент,
стеклянные карточки, сетка на фоне.

## Что внутри

| Файл | Что делает |
|---|---|
| `index.html` | Вся страница: шапка, первый экран, цифры, квиз, преимущества, этапы, вопросы, подвал |
| `styles.css` | Оформление и цветовая схема |
| `script.js` | Логика квиза, подбор комплектации, отправка заявки |
| `send.php` | Приём заявок: журнал, письмо, сообщение в MAX |
| `config.sample.php` | Образец настроек почты и мессенджера |
| `max-chat-id.php` | Помощник: показывает chat_id бота MAX |
| `setup-config.php` | Помощник: записывает `config.php`, задавая вопросы |
| `privacy.html` | Политика обработки персональных данных |
| `404.html` | Страница «не найдено» |
| `robots.txt`, `sitemap.xml` | Для поисковиков |
| `favicon.svg` | Иконка вкладки |
| `deploy/` | Скрипт настройки сервера и конфигурация nginx |

Сборка не нужна: ни npm, ни Node. Открывается двойным кликом по `index.html`,
на сервер заливается как есть.

## Что заменить перед запуском

Всё в одном месте — начало файла `script.js`, блок `SETTINGS`:

```js
var SETTINGS = {
  FORM_ENDPOINT: "/send.php",                 // куда отправлять заявки
  COMPANY: "Окна Профигрупп",

  SOURCE_LABEL: "Квиз форма",                 // метка источника заявки

  PHONES: [                                   // первый номер — основной
    { label: "8 (3522) 65-02-09", tel: "+73522650209", note: "городской" },
    { label: "+7 912 835-54-11", tel: "+79128355411", note: "мобильный" },
    { label: "555-411", tel: "555411", note: "короткий, для абонентов МТС" }
  ],

  CONTACT_EMAIL: "potolok-45@yandex.ru",      // временная почта для заявок

  MESSENGER_URL: "",                          // ссылка на МАКС, пока пусто
  MESSENGER_LABEL: "Написать в МАКС"
};
```

Первый номер из списка подставляется в шапку и во все кнопки «Позвонить»,
весь список выводится в подвале с пометками. Почта подставляется туда же.
Править их в `index.html` не нужно: в разметке номера продублированы, чтобы
страница оставалась рабочей без JavaScript, но при загрузке скрипт заменяет
их значениями из настроек.

Чтобы добавить или убрать номер, достаточно изменить массив `PHONES` —
в `label` пишется то, что видит человек, в `tel` — номер для дозвона без
пробелов и скобок.

Реквизиты компании, телефоны, домен и цифры в блоке статистики уже прописаны
и проверены. Политика обработки
персональных данных заполнена: наименование, ИНН, КПП, ОГРН, адрес. Текст
типовой, перед публикацией его стоит показать юристу.

## Куда приходят заявки

Заявку принимает `send.php`. Он работает по шагам:

1. **записывает заявку в журнал на сервере** — это происходит всегда;
2. **отправляет письмо**, если настроена почта;
3. **дублирует в мессенджер MAX**, если подключён бот.

Порядок именно такой намеренно: письмо и сообщение могут не уйти по десятку
причин, а обращение клиента теряться не должно. Если хотя бы журнал записан,
форма отвечает клиенту успехом. Журнал лежит в `/var/www/okna-leads`,
по одному файлу на месяц, вне папки сайта — из браузера его не скачать.

Посмотреть заявки на сервере:

```
cat /var/www/okna-leads/$(date +%Y-%m).txt
```

### Чтобы заявки приходили ещё и на почту

На облачном сервере нет почтовой программы, поэтому обычная отправка письма
не работает — нужен SMTP. Проще всего запустить помощник: он задаст вопросы
по одному и запишет настройки сам, редактировать файл руками не придётся.

```
php /var/www/okna/setup-config.php
```

Для Яндекса нужен именно **пароль приложения**, а не пароль от почты:
id.yandex.ru → Безопасность → Пароли приложений → Почта.

Помощник спрашивает и про MAX, и в конце предлагает отправить проверочное
сообщение — сразу видно, дошло или нет. Существующий `config.php` он не
перезаписывает без подтверждения и сохраняет копию прежнего рядом.

Если привычнее править вручную:

```
cd /var/www/okna
cp config.sample.php config.php
nano config.php
```

`config.php` в репозиторий не попадает и при выкладке не перезаписывается —
пароль остаётся только на сервере.

## Заявки в мессенджер MAX

Заявки можно дублировать в MAX — приходят мгновенно, как обычное сообщение.
Работает через бота: он нужен только как способ доставки, клиенты его не видят.

**Как подключить:**

1. Заведите бота в личном кабинете MAX для бизнеса — `business.max.ru`,
   раздел «Чат-боты» → «Создать». Форма просит название, телефон, сайт,
   описание и логотип 500×500. Создать бота командами в переписке нельзя,
   только через кабинет. После создания там же выдаётся токен.
2. Напишите своему боту любое сообщение, например «привет». Без этого ему
   некуда отправлять — так устроена защита от спама во всех мессенджерах.
3. На сервере выполните:

```
php /var/www/okna/max-chat-id.php ВАШ_ТОКЕН
```

   Скрипт покажет `chat_id` — рядом с каждым будет имя написавшего, текст
   его сообщения и пометка, личная это переписка или группа. Он же
   подскажет, какой способ авторизации подошёл.

   Сообщения MAX отдаёт по одному разу: если очередь пуста, попросите
   человека написать боту ещё раз.

4. Запишите токен и `chat_id` помощником:

```
php /var/www/okna/setup-config.php
```

Заявки могут приходить нескольким людям. Лучше завести в MAX группу,
добавить туда бота и указать её `chat_id` — состав участников потом
меняется в мессенджере, без правки настроек. Если добавить бота в группу
не удаётся, перечислите личные чаты через запятую: заявка уйдёт каждому.

Если MAX изменит формат обращения к API, в том же разделе есть `base_url`,
`auth` и `recipient_field` — поправить можно одной строкой, не трогая код.
Ответ сервера MAX при ошибке пишется в журнал ошибок PHP целиком, по нему
видно, что именно не подошло.

## Метки источника

Один и тот же бот и одна почта могут принимать заявки с нескольких сайтов,
поэтому каждая заявка помечается источником. Метка идёт в тему письма,
в сообщение в MAX и в журнал.

На этом сайте метка задаётся в `script.js`:

```js
SOURCE_LABEL: "Квиз форма",
```

На основном сайте в его форме ставится своя — например `"Основной сайт форма"`.
Если форма метку не прислала, берётся запасная из `config.php`.

## Настройка сервера

Делается один раз. На сервере, от root:

```
git clone https://github.com/sabutorin97-boop/https-4b5cf867-0cfc-4f31-be94-615f7580da8c-00-z5jwepwsh688.worf.replit.dev-.git /tmp/okna
bash /tmp/okna/deploy/setup-server.sh
```

Скрипт ставит nginx и PHP, создаёт каталог сайта и каталог заявок, включает
файрвол, выпускает бесплатный сертификат Let's Encrypt и заводит пользователя
`deploy` для автоматической выкладки. В конце он печатает четыре значения —
их нужно вписать в секреты репозитория.

Скрипт можно запускать повторно, уже настроенное он не ломает.

## Автоматическая выкладка

Настроена в `.github/workflows/deploy.yml`: при каждом изменении в ветке `main`
сайт сам загружается на сервер по SSH. Запустить вручную можно во вкладке
**Actions** кнопкой «Run workflow».

Секреты добавляются в **Settings → Secrets and variables → Actions →
New repository secret**:

| Секрет | Что вписать |
|---|---|
| `SSH_HOST` | IP сервера, например `5.42.122.203` |
| `SSH_USER` | `deploy` |
| `SSH_KEY` | приватный ключ целиком, вместе со строками BEGIN и END |
| `SSH_PATH` | `/var/www/okna` |

Все четыре значения печатает `setup-server.sh` при настройке сервера. Пароль
и ключ в коде не хранятся: GitHub подставляет их в момент выкладки и скрывает
в журнале.

На сервер уходят только файлы сайта. Документация, скрипты настройки и файлы
разработки остаются в репозитории. Файлы на сервере, которых нет в проекте,
не удаляются — чтобы случайно не снести `config.php` и чужое содержимое.

## Домен

Сайт рассчитан на `окна-курган-профигруп.рф`. В технических полях —
`canonical`, `og:url`, `sitemap.xml`, конфигурация nginx — домен записан
в латинице: `xn-----6kcboc8akc1afejndhfd0clr.xn--p1ai`. Так требуют nginx
и часть сервисов; браузер всё равно покажет кириллицу.

Чтобы домен заработал, в панели Timeweb он должен указывать на IP сервера.
Если домен привязан к другому сервису, привязку нужно снять и прописать
A-запись на нужный адрес. После обновления DNS выпустите сертификат:

```
certbot --nginx -d xn-----6kcboc8akc1afejndhfd0clr.xn--p1ai -d www.xn-----6kcboc8akc1afejndhfd0clr.xn--p1ai --redirect
```

## Если хостинг обычный, а не сервер

Для виртуального хостинга с Apache в папке `deploy` лежит `apache.htaccess` —
переименуйте его в `.htaccess` и положите рядом с сайтом. Он включает переход
на https, сжатие, кэш и страницу ошибки. На nginx этот файл не нужен.
