# Сервис генерации изображений — предложение по реализации, версия 2

Переработанное предложение по реализации веб-сервиса генерации и редактирования
изображений для российского рынка на внешних ИИ-провайдерах.

Исходное ТЗ (v1) сохранено в `docs/00-original-spec-v1.md`. Оно было сильным по
архитектуре — разделение контуров, идемпотентность, точечный туннель, каталог
моделей как данные, — но содержало дефекты, ломающие продакшен, и почти не
затрагивало дизайн, продуктовые механики, юридический контур и маркетинг.

## Главное из разбора

**Деньги.** Инвариант ночной сверки в v1 записан без `heldCredits` — в таком виде
он ложен при любом активном холде и давал бы критический алерт каждую ночь.
Резерв кредитов не был описан как атомарная операция, поэтому пакетный запуск
уводил бы баланс в минус. Фолбэк создавал второй холд, из-за чего пользователь
с балансом ровно в цену модели фолбэк не получал.

**Безопасность.** Текст обещал, что внутренний API биллинга наружу не публикуется,
но в compose контейнер стоял в сети периметра, а Caddy к нему обращался — между
интернетом и балансами всех пользователей оставался один секрет. Колбэки
провайдеров не аутентифицировались ничем: любой мог прислать `{"status":"success"}`.
Refresh-токены хранились в открытом виде, хотя пароли и API-ключи хэшировались.

**Провайдеры.** Слепой ретрай `submit` после сетевого таймаута — двойная оплата
провайдеру: таймаут чаще означает, что задача принята. Забор файла по URL из
внешнего источника без проверки адреса — готовый SSRF во внутреннюю сеть.

**Эксплуатация.** Бэкапов не было вовсе. Ротации логов не было — 160 ГБ диска
кончились бы сами. Egress без kill switch выпускал бы трафик с российского IP
при падении туннеля, что означает бан аккаунта с предоплатой.

Полный список — 35 дефектов и 9 пробелов в [`docs/01-review-v1.md`](docs/01-review-v1.md).

## Что добавлено сверх исправлений

* **Рецепты** (`Recipe`) — пайплайн шагов, продаваемый как один результат под
  площадку. Пользователь покупает «карточку для WB», а не вызов модели; один холд
  на весь пайплайн. Это то, что отличает продукт от обёртки над чужим API.
* **Стоп-кран** (`SystemState`) — глобальный дневной потолок расходов. В v1 были
  лимиты на пользователя и контроль балансов провайдеров, но одна ошибка в цикле
  могла израсходовать всю предоплату за ночь.
* **Дизайн-спецификация** — токены, шесть обязательных состояний каждого экрана,
  честный ETA из `p50/p90`, доступность, бюджеты производительности,
  русская типографика.
* **Экономика** — прайс с проверкой на худший сценарий по каждому тарифу,
  полная юнит-экономика пакета, механика бесплатной перегенерации,
  антифрод реферальной программы.
* **Юридический контур** — состав чека по 54-ФЗ (без него нарушение с первого
  платежа), согласия и уведомление РКН, закрывающие документы для B2B.
* **Маркетинг** — позиционирование против предметной съёмки, а не против
  Midjourney; программное SEO с работающим инструментом на странице;
  перенос результата гостя в аккаунт при регистрации.
* **Тестовая стратегия и mock-провайдер** — критерий приёмки этапа 1 в v1
  («при выключенном туннеле кредиты возвращаются») нечем было проверить.

## Проверки

Схемы Prisma проходят `prisma validate`, `docker-compose.yml` — `docker compose config`,
скрипты — проверку синтаксиса. `Caddyfile` в этом окружении не запускался
(нет демона Docker и бинарника Caddy) — конфигурацию нужно прогнать
через `caddy validate` перед первым деплоем.
